# Git Flow

<br/>
Git Flow는 Git 저장소에서 여러 작업을 체계적으로 관리할 수 있도록 도와주는 브랜치 관리 모델이다. Vincent Drieessen이 제안한 이 모델은 복잡한 프로젝트에서 협업과 릴리즈를 보다 명확하게 구분할 수 있도록 설계되었다.
<br/>

## Git-flow 전략 간단하게 살펴보기

<br/>
Git-flow는 5가지 종류의 브랜치가 존재한다. 항상 유지되는 메인 브랜치들(master, develop)과 일정 기간 동안만 유지되는 보조 브랜치들(feature, release, hotfix)이 있습니다.

<br/>

- 메인 브랜치
    - **master** : 제품으로 출시될 수 있는 브랜치
    - **develop** : 다음 출시 버전을 개발하는 브랜치
- 보조 브랜치
    - **feature** : 기능을 개발하는 브랜치
    - **release** : 이번 출시 버전을 준비하는 브랜치
    - **hotfix** : 출시 버전에서 발생한 버그를 수정하는 브랜치

처음엔 master에서 develop을 만들어 master와 deelop 두 개의 브랜치로 시작한다.
develop 브랜치는 상시로 버그를 수정한 커밋들이 추가된다. 새로운 기능 추가 작업이 있는 경우 develop 브랜치에서 feature 브랜치를 생성한다. feature 브랜치는 언제나 develop 브랜치로부터 시작하게 된다. 기능 추가 작업이 완료되었다면 feature 부랜치는 develop 브랜치로 merge 된다. develop에 이번 버전에 포함되는 모든 기능이 merge 되었다면 QA를 하기 위해 release 브랜치를 생성한다. QA를 진행하면서 발생한 버그들은 release 브랜치에 수정된다. QA를 무사히 통과했다면 release 브랜치를 master와 develop 브랜치로 merge한다. 만일 배포된 master 브랜치에서 버그가 발생된다면 master에서 hotfix 브랜치를 생성하여 버그 픽스를 진행한다. 그리고 종료된 hotfix를 master와 develop에 merge한다. 마지막으로 출시된 master 브랜치에서 버전 태그를 추가한다.
