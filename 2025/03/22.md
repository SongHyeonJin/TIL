# **CI / CD**
소프트웨어 개발과 배포 프로세스의 자동화 및 최적화를 위한 방법론이다.<br/>
이는 개발자가 보다 빠르고 안정적으로 코드를 통합, 테스트, 배포할 수 있도록 도와주며, 최종적으로 사용자에게 높은 품질의 스프트웨이를 제공하는 것을 목표로 한다.

## **CI (Continuous Integration, 지속적인 통합)**

- **빈번한 코드 통합** : 개발자들은 자신이 작업한 코드를 자주, 보통 하루에 여러번 메인 브랜치에 통합한다.
- **자동 빌드 및 테스트** : 코드가 통합될 때마다 자동 빌드와 테스트가 실행되어, 오류나 충돌을 빠르게 발견한다.
- **빠른 피드백** : 개발자들은 자신의 코드에 문제가 발생했을 때 즉각적인 피드백을 받게 되어 문제를 조기에 해결할 수 있다.

### 기대 효과
- **문제 조기 발견** : 작은 단위의 변경 사항에 대해 지속적으로 테스트하므로, 오류가 발생하더라도 원인 파악이 용이하다.
- **협업 효율성 향상** : 개발자 간의 통합 주기가 짧아져 팀원들이 동시에 작업할 때 생길 수 있는 통합 문제를 최소화한다.

## **CD**

-  **Continuous Delivery(지속적인 서비스 제공)** : 자동화된 빌드와 테스트를 거친 후, 배포 준비까지의 과정을 자동화하여 언제든지 실제 운영 환경에 배포할 수 있는 상태를 유지한다.

- **Continuous Deployment(지속적인 배포)** : Continuous Delivery의 확장으로, 테스트를 통과한 변경 사항이 자동으로 실제 운영 환경에 배포된다.

### 기대 효과
- **빠른 릴리즈 주기** : 소프트웨어 업데이트가 신속하게 이루어져 시장 반응에 민첩하게 대응할 수 있다.
- **리스크 분산** : 작은 변경 사항을 자주 배포하여, 큰 규모의 문제 발생 시 원인을 신속히 파악하고 대응할 수 있다.

## **CI/CD 파이프라인 단계**

<br/>

<br/>

1. **코드 커밋** : 개발자가 소스 코드 저장소에 변경 사항을 커밋한다.
2. **빌드 단계** : 커밋된 코드를 자동으로 빌드하여 실행 파일이나 배포 가능한 아트팩트를 생성한다.
3. **테스트 단계** : 코드 빌드의 결과물이 다른 컴포넌트와 잘 통합되는 지 확인하는 과정이다.
    - 유닛 테스트 : 개별 기능 또는 모듈을 테스트한다.
    - 통합 테스트 : 모듈 간 상호작용을 테스트한다.
    - 기능 테스트 : 전체 애플리케이션의 기능이 정상 작동하는 지 확인한다.
4. **배포 준비 단계(Continuous Delivery)** : 테스트를 통과한 코드를 스테이징 환경 등 배포 준비 환경에 배포하여 최종 검증을 진행한다.
5. **자동 배포(Continuous Deployment)** : 최종 검증 후, 운영 환경에 자동으로 배포한다.
6. **모니터링 및 롤백** : 배포 후 애플리케이션의 성능, 오류, 로그 등을 모니터링하고, 문제가 발생하면 신속히 롤백할 수 있도록 한다.

<br/>

### **CI/CD 구성요소에 따른 장점**
- **Build** : 자동화된 빌드를 통해 일관된 결과를 보장하여, 개발자들이 코드 통합 시 발생할 수 있는 문제를 신속히 파악할 수 있다.
- **Test** : 자동화된 테스트로 코드 변경에 즉각적인 피드백을 받아, 개발자들이 빠르게 문제를 확인하고 수정할 수 있다.
- **Release** : 항상 배포 가능한 상태를 유지함으로써, 개발자들이 릴리즈 준비에 소요되는 시간을 줄이고 핵심 기능 개발에 집중할 수 있다.
- **Deploy** : 자동화된 배포 프로세스로 배포 오류를 최소화하여, 개발자들이 안정적인 운영 환경 유지와 효율적인 협업에 전념할 수 있다.

<br/>
CI/CD를 공부하면서 개발자에게 얼마나 큰 효율과 안정성을 주는지 알게 되었다. 특히 자동화된 피드백과 배포 과정을 통해 협업과 코드 품질이 훨씬 좋아진다는 걸 느꼈다. 앞으로 개인 혹은 팀 프로젝트에서 직접 CI/CD 파이프라인을 구성해보며 더 실전 경험을 쌓고 싶다는 생각이 들었다.
