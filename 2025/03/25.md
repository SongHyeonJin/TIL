# Spring Security에서 403 Forbidden 응답 커스터마이징하기

## 개요
Spring Security를 사용할 때, 권한이 없는 사용자가 보호된 리소스에 접근하면 기본적으로 403 Forbidden 에러 페이지가 반환된다. 이 기본 응답을 JSON 형태로 커스터마이징하여 클라이언트가 처리하기 쉽게 만드는 방법을 정리했다.

## ⁉️ 도입 배경
개발 중 관리자 전용 페이지(`/admin/**`)에 접근 제한을 걸어두었고, 권한 없는 사용자가 접근할 경우 전역 예외처리 형식으로 **"권한이 없습니다"** 같은 JSON 응답을 받고 싶었다.

전역 예외처리를 위해 `@ControllerAdvice`를 사용하여 `ErrorResponseDto` 형식으로 예외를 응답하도록 설정해두었지만, **403 Forbidden 에러는 해당 전역 예외 처리에서 잡히지 않았다.**

그 이유는, Spring Security에서 발생하는 403 에러는 **필터(Filter) 레벨에서 발생**하기 때문에, DispatcherServlet을 거치지 않고 바로 응답이 내려오기 때문이다.

나는 혼자 Postman으로 백엔드 테스트를 하고 있기 때문에, 에러가 발생했을 때 정확한 메시지를 JSON 형식으로 바로 확인하고 싶었고, **권한 관련 예외도 내가 정의한 전역 응답 포맷으로 내려보내기 위해** Spring Security의 `AccessDeniedHandler`를 커스터마이징해서 적용하게 되었다.

## 구현 방법

1. **CustomAccessDeniedHandler 클래스 생성**

    ```java
    @Component
    public class CustomAccessDeniedHandler implements AccessDeniedHandler {

        private final ObjectMapper objectMapper = new ObjectMapper();

        @Override
        public void handle(HttpServletRequest request, 
                           HttpServletResponse response, 
                           AccessDeniedException accessDeniedException) throws IOException {
            response.setStatus(HttpServletResponse.SC_FORBIDDEN);
            response.setContentType(MediaType.APPLICATION_JSON_VALUE);
            response.setCharacterEncoding("UTF-8");

            ErrorResponseDto errorResponseDto = new ErrorResponseDto(ExceptionEnum.NOT_ALLOW);
            String responseBody = objectMapper.writeValueAsString(errorResponseDto);

            response.getWriter().write(responseBody);
        }
    }
    ```

    위의 클래스는 `AccessDeniedHandler`를 구현하여, 권한이 없는 사용자가 접근할 때 JSON 형태의 응답을 반환한다.

2. **SecurityConfig에 핸들러 등록**

    ```java
    @Configuration
    @EnableWebSecurity
    @RequiredArgsConstructor
    public class SecurityConfig {

        private final JwtAuthenticationFilter jwtAuthenticationFilter;
        private final CustomAccessDeniedHandler customAccessDeniedHandler;

        ` ` `

        @Bean
        public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
            http
                    .cors(cors -> cors.configurationSource(corsConfigurationSource()))
                    .csrf(AbstractHttpConfigurer::disable)
                    .authorizeHttpRequests(authorizeRequests -> authorizeRequests
                                .requestMatchers("/api/signup", "/api/login").permitAll()
                                .requestMatchers("/admin/**").hasRole("ADMIN")
                                .anyRequest().authenticated()
                            )
                            .exceptionHandling(exception -> exception
                                .accessDeniedHandler(customAccessDeniedHandler)
                            );
            http.addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
            return http.build();
        }

        ```

    }
    ```

    위의 설정을 통해 `CustomAccessDeniedHandler`를 Security 설정에 등록하여, 권한이 없는 요청에 대해 커스터마이징된 응답을 반환하도록 했다.

## 🛠️ 추가로 개선한 점

JWT 토큰이 만료되었을 경우, 기존에는 서버 콘솔에만 에러 로그가 찍히고 클라이언트(예: Postman)에는 명확한 응답이 내려가지 않았다.그래서 `AuthenticationEntryPoint`를 커스터마이징하여, JWT가 만료되었거나 인증 정보가 없는 경우에도 `ErrorResponseDto` 형식의 JSON 응답이 내려가도록 처리했다.

이를 통해 사용자는 원하는 메시지를 JSON으로 정확하게 받아볼 수 있게 되었고, 전역적으로 통일된 예외 응답 포맷을 유지할 수 있게 되었다.

> **SecurityConfig**는 `.authenticationEntryPoint(커스터마이징한 클래스)`를 exceptionHandling 안에 추가해주면 된다.
