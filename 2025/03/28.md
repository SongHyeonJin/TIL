# Spring Boot + EC2 + MySQL 연동 배포 실습 기록

오늘은 **Amazon EC2** 인스턴스에 **MySQL 8**을 직접 설치하고, **Spring Boot**에서 해당 DB를 연결하는 환경을 구성했다.  
설치 중 다양한 오류와 이슈를 겪었고, 이를 해결한 전체 흐름을 정리한다.

## 🖥️ EC2 SSH 접속 시 실수

- EC2 인스턴스를 생성하고 SSH 접속을 시도했는데, 기존에 **Ubuntu 계정**을 사용하던 습관 때문에 접속이 안 됐다.
- **Amazon Linux 2**에서는 기본 계정이 `ubuntu`가 아니라 `ec2-user`라는 점을 놓쳐 헤맸다.
  
### ✅ 올바른 SSH 접속 방식

```bash
ssh -i 키페어 ec2-user@<EC2 퍼블릭 IP>
```

### 초기 환경 업데이트 및 개발 툴 설치

```bash
# 패키지 업데이트
sudo yum update -y

# Git 설치
sudo yum install git -y

# Java 설치 (Amazon Corretto 17)
# 기본 저장소에 이미 열려 있는 경우에는 enable 생략 가능
sudo amazon-linux-extras enable corretto17
sudo yum install java-17-amazon-corretto -y

# Java 설치 확인
java -version
```

## 작업 흐름 요약

- EC2 인스턴스에 MySQL 8 설치 및 실행
- 시간대 설정 (UTC → KST)
- DB 및 사용자 생성
- 외부 접속 허용 (`bind-address`, 보안 그룹)
- Spring Boot 연동 준비
- 발생한 오류 해결


## 🛠️ 1. MySQL 8 설치 (Amazon Linux 2)

```bash
# MySQL 저장소 등록
sudo rpm -Uvh https://repo.mysql.com/mysql80-community-release-el7-5.noarch.rpm

# 필수 의존성 설치
sudo yum install ncurses-compat-libs -y

# GPG 키 오류가 발생하여 --nogpgcheck 옵션 사용
sudo yum install mysql-community-server --nogpgcheck --enablerepo=mysql80-community -y
```

설치 후 MySQL을 실행하고 자동 시작 등록

```bash
sudo systemctl start mysqld
sudo systemctl enable mysqld
```

시작 후 MySQL 실행 상태 확인

```bash
sudo systemctl status mysqld
```

## 🔐 2. MySQL 초기 보안 설정

# 초기 비밀번호 확인

```bash
# 초기 비밀번호 확인
sudo grep 'temporary password' /var/log/mysqld.log

# 보안 설정 실행
sudo mysql_secure_installation
```

## 🕧 3. 서버 시간대 한국(KST)으로 변경

```bash
sudo timedatectl set-timezone Asia/Seoul
```

## 4. 데이터베이스 및 유저 생성

```sql
-- DB 생성
CREATE DATABASE `coupang-clone` CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- 사용자 생성 및 권한 부여
CREATE USER '사용자이름'@'%' IDENTIFIED BY '비밀번호';
GRANT ALL PRIVILEGES ON `coupang-clone`.* TO '사용자이름'@'%';
FLUSH PRIVILEGES;
```

##  5. 외부 접속 허용 설정

MySQL 기본 설정은 외부 접속을 막고 있기 때문에 다음 설정을 추가

```bash
sudo vi /etc/my.cnf
```

```ini
[mysqld]
bind-address = 0.0.0.0
```

MySQL 서버 재시작

```bash
sudo systemctl restart mysqld
```
또한 AWS EC2 보안 그룹에서 3306 포트 인바운드 허용(EC2 퍼블릭 IP) 설정도 추가

## 6. Spring Boot 애플리케이션 빌드

**로컬에서 빌드**: 프로젝트 디렉토리에서 아래 명령어를 실행하여 `.jar` 파일을 빌드

```bash
./gradlew clean build -x test
```

**빌드 파일 확인**: build/libs/ 폴더에 .jar 파일이 생성되었는지 확인

## 7. 빌드된 .jar 파일 EC2에 복사

**파일 전송**: SCP 명령어를 이용해 로컬에서 EC2로 `.jar` 파일과 `application.yml`을 전송

```bash
# 생성한 jar 파일
scp -i 키페어.pem build/libs/*.jar ec2-user@<EC2 퍼블릭 IP>:/home/ec2-user/
# application.yml 파일
scp -i 키페어 src/main/resources/application.yml ec2-user@<EC2 퍼블릭 IP>:/home/ec2-user/
```

**파일 복사 후 EC2 확인**: EC2에 접속하여 파일이 정상적으로 복사되었는지 확인

```bash
ls -l /home/ec2-user
```

## 8. EC2에서 애플리케이션 실행

**애플리케이션 실행**: `nohup` 명령어를 이용해 백그라운드에서 애플리케이션 실행

`nohup`으로 백그라운드에서 실행시 **SSH 세션 종료 후에도 애플리케이션은 계속 실행됨**

```bash
nohup java -jar coupangclone-0.0.1-SNAPSHOT.jar --spring.config.location=file:/home/ec2-user/application.yml > app.log 2>&1 &
```

**로그 확인**: 실행 로그는 `tail -f` 명령어로 확인

```bash
tail -f app.log
```

## 9. Postman으로 API 테스트

**API 요청**: Postman을 사용하여 애플리케이션이 정상 동작하는지 테스트

```http
POST http://<EC2 퍼블릭 IP>:8080/api/signup
```

**응답 확인**: 성공적인 응답(`200 OK`)을 받으면 배포 완료~!

## 10. 애플리케이션 종료

**실행 중인 프로세스 확인**: 아래 명령어로 실행 중인 Java 프로세스를 확인

```bash
ps -ef | grep java
```

**프로세스 종료**: `kill` 명령어로 해당 프로세스를 종료

```bash
kill <PID>
```
